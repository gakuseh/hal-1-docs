Bug List
Member changeOpFreq_e22_900t22s (R2_E22Channel915 channel)
Runs at 38400 baud after init, but CONFIG mode accepts only 9600. The write fails and writeConfig_e22_900t22s() returns before switching back to TRANS, leaving the module in CONFIG mode. The driver's REG2 copy is already changed by then, so getOpFreq_e22_900t22s() reports a channel the module is not on.
Member CTRLs_PID ()
The dead-band constant is π/180 (1 deg/s expressed in rad/s) but it is compared with a rate in deg/s, so the dead-band is about 0.017 deg/s instead of 1 deg/s. The comment above it says 6 deg/s.
Member CTRLs_STATESPACE ()
When it returns early, the CTRLs task calls it again immediately with no delay, so while ALLOW_ACTUATION is set and g_ctrls_enabled is clear, the CTRLs task spins at Realtime priority.
Member CtrlsSensorSnapshot::altitude_m
CTRLs_STATESPACE() passes this to the EKF and controller, whose weather table is indexed by height above the launch site, so every weather lookup is off by the site's elevation.
Member g_ctrls_enabled
Only Telemetry::processPyros() sets it back to true, and nothing calls that. The pad tare (after 3 minutes still on the pad) clears it, so in a normal launch the state-space controller never actuates: CTRLs_STATESPACE() returns at its first check.
Member Sensors::Init ()
The body of if (mag.Init() != 0) is commented out, so that if now guards the next statement: g_telemNow and g_telemPrev are zeroed only when the magnetometer fails to initialize.
Member Telemetry::processCmd (uint8_t cmd)

The channel-change path has three problems:

  • changeOpFreq_e22_900t22s() sends the config at 38400 baud, but the E22 accepts config commands only at 9600. The write fails and leaves the module in CONFIG mode, so the link stays down until reboot.
  • des_cfg.REG2 is never updated, so after a change every packet repeats the config write.
  • encodeAndSend() always puts GLOBAL_RADIO_CHANNEL in the header, so transmissions stay on the old channel. Nothing checks the byte is a valid channel (52–78), so SERVO_OFFSET_CMD_BYTE or 0 takes the same path.

The echo never reaches GND. The Radio task overwrites HALOutData from g_telemNow before the next send.
