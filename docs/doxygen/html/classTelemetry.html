Detailed Description

Frames packets, schedules TX and RX on the E22, and applies GND commands.

There is one global instance, telem in main.cpp. FC_Init() calls Init() once at boot. After that only the Radio task uses it: each loop copies g_telemNow into HALOutData and calls Update().

Update() follows a fixed duty cycle. Every 5 s it opens a receive window of up to 2 s; the rest of the time each call sends one telemetry frame.

Note
Older comments describe an FC_MASTER / GND_MASTER scheme with TX_BURST_SIZE and GND_MASTER_TIMEOUT_MS. It is not implemented, and the members that supported it are unused.

◆ Init()

uint8_t Telemetry::Init ( )

Configures the E22 module and leaves it in TRANS mode.

Fills des_cfg with the HAL-1 settings: address 0x0706, NETID 0xE6, UART 38400 8N1, 4.8 kbps air rate, 240-byte sub-packets, 22 dBm, channel GLOBAL_RADIO_CHANNEL, RSSI byte enabled, fixed-point mode. Then calls init_e22_900t22s(). Blocks for a few seconds.

Returns
0 on success, 1 on failure. FC_Init() retries every 100 ms until this succeeds.

◆ processCmd()

void Telemetry::processCmd ( uint8_t cmd)
private

Applies a GND command byte.

Echoes cmd into HALOutData.CommandResponseByte. 217 (SHUTDOWN_KEEPALIVE) sets shutdownFlag and clears g_ctrls_enabled. Any other value is treated as an E22 channel and passed to changeOpFreq_e22_900t22s() if it differs from des_cfg.REG2.

Parameters
cmdGndStationData::CommandByte from the decoded frame.
Bug

The channel-change path has three problems:

  • changeOpFreq_e22_900t22s() sends the config at 38400 baud, but the E22 accepts config commands only at 9600. The write fails and leaves the module in CONFIG mode, so the link stays down until reboot.
  • des_cfg.REG2 is never updated, so after a change every packet repeats the config write.
  • encodeAndSend() always puts GLOBAL_RADIO_CHANNEL in the header, so transmissions stay on the old channel. Nothing checks the byte is a valid channel (52–78), so SERVO_OFFSET_CMD_BYTE or 0 takes the same path.

The echo never reaches GND. The Radio task overwrites HALOutData from g_telemNow before the next send.

Calls recieve_e22_900t22s() with the scheduler suspended, decodes the frame, copies the servo offsets into g_gndData under g_ctrls_sensor_mutex (offsets 1 and 2 swapped), then calls processCmd().

◆ Update()

uint8_t Telemetry::Update ( )

Runs one Radio-task cycle: receive if a window is due, otherwise send.

If 5 s have passed since the last window opened, polls AUX for up to 2 s. Whenever AUX is low it calls receiveCommands(), and it returns as soon as one frame decodes. Otherwise, or if the window ends without a valid frame, it sends HALOutData.

Returns
0 if a GND frame was decoded (nothing was sent this call), or E22_NO_DATA if a telemetry frame was sent. Send errors are ignored.
Warning
The receive window busy-waits without yielding at the Radio task's Realtime priority, so lower-priority tasks get no CPU for up to 2 s.
