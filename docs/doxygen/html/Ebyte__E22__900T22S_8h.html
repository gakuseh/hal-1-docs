Detailed Description

Driver for the EBYTE E22-900T22S LoRa UART radio module.

The module is wired to UART8 plus three GPIOs: M0 and M1 select the mode (see EBYTE_MODE) and AUX goes low while the module is busy. All UART transfers are blocking HAL calls, and the waits use vTaskDelay(), so every function here must run inside a FreeRTOS task.

The driver keeps one static copy of the config, so it supports one module.

Note
The internal UART helpers always use huart8, whatever config_e22_900t22s::huart says.
CONFIG mode accepts commands only at 9600 baud, but after init_e22_900t22s() the MCU UART runs at 38400. Every function that rewrites the config after init (changeOpFreq_e22_900t22s(), setAddress_e22_900t22s(), the parameter setters, reset_e22_900t22s()) therefore talks to the module at the wrong baud rate.

◆ init_e22_900t22s()

int8_t init_e22_900t22s ( config_e22_900t22s * cfg)

Powers up the module, writes cfg to its flash, verifies it, and enters TRANS mode.

Switches the MCU UART to 9600 baud for CONFIG mode, releases RADIO_RST, waits for AUX, writes the config, reads it back and compares (rewriting once if it differs), then switches the MCU UART to 38400 and the module to TRANS mode. Takes a few seconds.

Parameters
cfgRegister values plus the UART and GPIO handles to use.
Returns
E22_OK; E22_ERR_INVALID_PARAM if cfg is null; E22_ERR_UART or E22_ERR_TIMEOUT if a step fails; or 1 if the read-back still differs after the rewrite.
Warning
The final MCU baud rate is hard-coded to 38400 and must match the UART bits in REG0.

◆ recieve_e22_900t22s()

int16_t recieve_e22_900t22s ( uint8_t * buffer,
uint16_t expected_payload_len )

Blocking read of one incoming frame from the module.

Reads the frame (5 header bytes + expected_payload_len + 4 trailer bytes), plus 1 for the RSSI byte the module appends and 4 guard bytes that absorb leftovers from an earlier timed-out read. The timeout is the time those bytes take at 38400 baud plus 50 ms (about 57 ms for a 16-byte payload). Sync and checksum checks are left to the caller (Telemetry::decodeData()).

Parameters
[out]bufferMust hold at least expected_payload_len + 14 bytes.
expected_payload_lensizeof the payload struct being received.
Returns
Number of bytes placed in buffer (a partial read counts if at least 7 bytes arrived), or -2 if fewer than 7 arrived.
