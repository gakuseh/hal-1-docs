Detailed Description

FreeRTOS task bodies and the flight state machine.

MX_FREERTOS_Init() in freertos.c creates these tasks:

Task Entry Priority Stack
defaultTask FC_Init() Normal 4 KB
Radio Radio() Realtime 4 KB
updateSensor updateSensorTask() Realtime 4 KB
updateData updateDataTask() Realtime 4 KB
CTRLs CTRLs() Realtime 12 KB
SDLog SDLogTask() AboveNormal 2 KB
ICTare Initial_Condition_Tare() BelowNormal 512 B

Every task except FC_Init() waits for initDone. Data moves between them through g_telemNow, g_SensorData and g_gndData under g_ctrls_sensor_mutex, and the sensor pipeline is chained with task notifications: updateSensorTask() → updateDataTask() → CTRLs().

◆ CTRLs_PID()

void CTRLs_PID ( )

Backup roll damper: one proportional step, then wait for the next frame.

The CTRLs task calls it when actuation is allowed (after burnout) but ignition was never latched, so STATE_BACKUP_PID is still set. It commands both canards to −0.30° per deg/s of roll rate, limited to ±7°, writes the command plus GND trim into g_telemNow.servoTarget1/2, waits up to 10 ms for the next frame, and returns.

Bug
The dead-band constant is π/180 (1 deg/s expressed in rad/s) but it is compared with a rate in deg/s, so the dead-band is about 0.017 deg/s instead of 1 deg/s. The comment above it says 6 deg/s.
Note
Does not check g_ctrls_enabled, so GND command 217 does not stop it.

◆ CTRLs_STATESPACE()

void CTRLs_STATESPACE ( )

Main roll controller: EKF plus gain-scheduled control law, in its own loop.

Reloads the Control Freak config on every entry; the Physics, EKF and ControlLaw objects are built once. Each iteration:

  1. Zeroes the servos and returns if g_ctrls_enabled or ALLOW_ACTUATION is clear, or STATE_BACKUP_PID is set.
  2. Takes the latest g_SensorData sample if it is fresh.
  3. Runs EKF::update(), or EKF::predictOnly() without a fresh sample, and the roll effectiveness monitor.
  4. Detects apogee (modelled vertical speed below 3 m/s after burnout), which disables control and strobes the LED for 2 s.
  5. Computes the command with ControlLaw::computeControl() and drives both canards with it.
  6. Waits up to 10 ms for the next frame.

While active it also logs a DYN line to the SD card every 20 ms. Flight time comes from g_SensorData.flight_time_s, which starts at liftoff detection in Sensors::Update().

Bug
When it returns early, the CTRLs task calls it again immediately with no delay, so while ALLOW_ACTUATION is set and g_ctrls_enabled is clear, the CTRLs task spins at Realtime priority.
Warning
The DYN log calls SD_LogNewline(), which syncs to the card, from inside the control loop.

◆ FC_Init()

void FC_Init ( void * )

Boot task (CubeMX's defaultTask): brings up every subsystem, then suspends itself.

Starts the DWT timer and turns the user LED on, then initializes, in order, the sensors, the radio, the servos and the SD card. Each step retries every 100 ms until it succeeds; the LED blinks while the SD card is retrying. When all four are up it sets initDone, toggles the LED, and suspends.

Warning
Every step retries forever, so one missing piece (no SD card, a GPS that never answers, servos not attached) keeps every other task, the radio included, from starting.

◆ Initial_Condition_Tare()

void Initial_Condition_Tare ( void * )

Pad-tare task: waits for 3 minutes of stillness, then asks updateDataTask() to tare.

Monitors the IMU for a 3-minute stability window (rocket sitting upright on the pad), sampling g_telemNow at 10 Hz. A sample counts as still when every change from the previous one is under TARE_ACC_DELTA_G and TARE_GYRO_DELTA_DPS; any larger change restarts the TARE_STABILITY_MS clock. When the clock runs out it sets g_request_tare, so updateDataTask can zero the attitude estimator, pad altitude, and CTRLs_t in a mutex-safe context, and suspends itself. The tare therefore happens once per boot.

void Radio ( void * )

Radio task: sends telemetry and listens for ground-station commands.

Each loop copies g_telemNow into telem.HALOutData (and g_telemPrev) under g_ctrls_sensor_mutex, subtracting g_alt_pad_m so altitude goes out as AGL, then calls Telemetry::Update() and toggles the user LED. There is no sleep in the loop; Telemetry::Update() paces it through the E22's busy waits.

◆ SDLogTask()

void SDLogTask ( void * )

Logging task: writes three CSV-style lines to the SD card every 10 ms.

After a header, each loop logs SENS1 (position, altitude, vertical velocity, temperature), SENS2 (acceleration, rates, attitude, servo commands, RSSI, pyro flags) and GPS (position, UTC time, satellites, HDOP). g_telemNow is copied under the mutex; g_GPS is copied without it.

Note
Each SD_LogNewline() syncs to the card, so the real rate is limited by how fast the card syncs. The task gets no CPU during the radio's 2 s receive window.

◆ updateDataTask()

void updateDataTask ( void * )

Data task: filtering, attitude, vertical velocity, and the flight state machine.

Woken by updateSensorTask() after each frame (100 ms timeout). Holding g_ctrls_sensor_mutex, it performs a pending pad tare, updates g_dt, filters the frame with SensorFilters::apply(), runs the attitude estimator, and computes vertical velocity. Then it runs the latched state machine:

  • Ignition: vertical acceleration above LIFTOFF_ACCEL_G for IGNITION_SUSTAIN_MS. Sets STATE_IGNITION and clears STATE_BACKUP_PID.
  • Burnout: vertical acceleration below BURNOUT_ACCEL_G for BURNOUT_SUSTAIN_MS. Sets STATE_BURNOUT and, unless locked out, ALLOW_ACTUATION.
  • Lockout (permanent until the next tare): |pitch| above MAX_PITCH_ANGLE_DEG at any time, or after burnout |vertical velocity| below MIN_ACTUATION_VEL_MS or more than MAX_ACTUATION_DURATION_MS elapsed. Clears ALLOW_ACTUATION and g_ctrls_enabled.

Finally it notifies the CTRLs task.

The pad tare resets the attitude estimator, records g_alt_pad_m, and resets the state machine, which includes clearing g_ctrls_enabled. See the bug note on g_ctrls_enabled: nothing sets it again afterwards.
